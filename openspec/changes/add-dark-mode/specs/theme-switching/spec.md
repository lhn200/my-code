## ADDED Requirements

### Requirement: 主题模式选择

前端 SHALL 提供 `light`、`dark`、`system` 三种主题模式，用户可以在界面中随时切换，切换后当前页面 MUST 立即生效，无需刷新。

#### Scenario: 首次访问默认跟随系统

- **WHEN** 用户首次访问且本地没有保存过主题选择
- **THEN** 生效主题 MUST 等于操作系统当前配色（系统为深色则显示深色，否则显示浅色）
- **AND** 切换控件 MUST 显示"跟随系统"为选中态

#### Scenario: 手动选择深色或浅色

- **WHEN** 用户在切换控件中选择"深色"或"浅色"
- **THEN** 页面 MUST 立即切换到对应主题
- **AND** 生效主题 MUST 不再随系统配色变化

#### Scenario: 从手动模式恢复跟随系统

- **WHEN** 用户在手动模式下选择"跟随系统"
- **THEN** 页面 MUST 立即按当前系统配色重新渲染
- **AND** 后续系统配色变化 MUST 再次自动同步

### Requirement: 主题选择持久化

系统 SHALL 将用户显式选择的主题模式保存在浏览器本地存储中，并在后续访问时恢复。

#### Scenario: 刷新后保持选择

- **WHEN** 用户手动选择"深色"后刷新页面
- **THEN** 页面 MUST 仍以深色渲染
- **AND** 切换控件 MUST 显示"深色"为选中态

#### Scenario: 存储值缺失或非法

- **WHEN** 本地存储中没有主题值，或值不是 `light` / `dark` / `system` 之一
- **THEN** 系统 MUST 回退到 `system` 模式，不得抛出错误或停留在未定义状态

#### Scenario: 本地存储不可用

- **WHEN** 浏览器禁用本地存储导致读写失败
- **THEN** 主题切换 MUST 在当前会话内继续可用
- **AND** 系统 MUST NOT 因存储异常中断页面渲染

### Requirement: 首屏无主题闪烁

系统 SHALL 在首屏内容绘制前应用已持久化的主题，避免先渲染浅色再切换为深色。

#### Scenario: 深色偏好用户加载页面

- **WHEN** 已保存"深色"的用户打开或刷新任意前端页面
- **THEN** 首次可见渲染 MUST 已是深色，不得出现浅色闪帧

#### Scenario: 首屏脚本读取到损坏值

- **WHEN** 首屏主题脚本读取到无法识别的存储值
- **THEN** 脚本 MUST 回退到系统配色，且不得阻塞页面加载

### Requirement: 系统主题联动

在 `system` 模式下，系统 SHALL 监听操作系统配色变化并实时更新界面；在手动模式下 MUST 忽略系统变化。

#### Scenario: 跟随系统时系统切换配色

- **WHEN** 主题模式为 `system` 且操作系统在浅色与深色之间切换
- **THEN** 页面 MUST 在无需刷新的情况下切换到对应主题

#### Scenario: 手动模式下系统切换配色

- **WHEN** 主题模式为 `light` 或 `dark` 且操作系统配色发生变化
- **THEN** 页面主题 MUST 保持不变

### Requirement: 主题由样式变量驱动

页面颜色 SHALL 通过统一的 CSS 变量（design tokens）提供，深浅主题只切换变量取值；组件不得硬编码浅色专用色值。

#### Scenario: 深色主题下渲染组件

- **WHEN** 当前主题为深色
- **THEN** 页面背景、文本、边框、输入框、按钮等基础样式 MUST 使用深色变量值
- **AND** 正文文本与背景的对比度 MUST 满足 WCAG AA（≥ 4.5:1）

#### Scenario: 新增组件继承主题

- **WHEN** 开发者新增一个使用主题变量的组件
- **THEN** 该组件 MUST 在浅色与深色下均可读，无需为深色单独编写样式分支

#### Scenario: 切换主题时的过渡

- **WHEN** 用户切换主题
- **THEN** 颜色变化 MAY 使用短暂过渡，但不得导致内容不可读或布局跳动
